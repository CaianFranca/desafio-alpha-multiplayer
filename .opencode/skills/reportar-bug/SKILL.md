# Reportar bug

Crie uma issue de bug a partir do que foi descoberto na sessão e coloque-a na
coluna **Reports de Bug** do Project do repo.

## Regra principal de idioma

Escreva todo o conteúdo da issue em português brasileiro, incluindo título,
seções do corpo e descrições. Preserve em seu idioma original apenas
identificadores que precisam ser exatos: comandos, mensagens de erro, trechos
de log, nomes de arquivos, símbolos de código e labels.

## Quando usar

Use esta skill quando, durante a sessão, um bug for **confirmado**: um erro
reproduzível, um teste falhando por causa real no código, um comportamento que
diverge do esperado com causa identificada. Não use para suspeitas sem
evidência, limitações conhecidas ou coisas que você mesmo vai corrigir na hora
nesta mesma sessão.

## Processo

### 1. Reunir contexto do bug

Trabalhe com o que a sessão já produziu. Colete:

- **Comportamento esperado** — o que deveria acontecer, segundo specs, ADRs ou
  o próprio código.
- **Comportamento observado** — o que aconteceu de fato, com o erro exato.
- **Passos para reproduzir** — sequência concreta e mínima (comandos, requests,
  cliques, seeds) que leva ao erro.
- **Evidências** — stack traces, logs, mensagens de erro, saídas de testes.
  Colete trechos reais da sessão, não parafraseie.
- **Arquivos suspeitos** — arquivos e linhas onde a causa provável vive.
- **Contexto da sessão** — o que estava sendo feito quando o bug apareceu
  (feature em andamento, comando rodado, commit recente).

Se algo essencial estiver faltando, investigue no código antes de rascunhar —
não deixe "desconhecido" no draft se uma leitura rápida de 2-3 arquivos
responde.

### 2. Detectar a área

Analise os arquivos envolvidos no bug e escolha **exatamente uma** label de
área, além da label `bug`:

- `frontend` — interface web e cliente do jogo
- `backend` — servidores, APIs e regras de negócio (`packages/engine`,
  `packages/shared`, contratos OpenAPI)
- `banco-de-dados` — PostgreSQL, Redis, migrations, persistência
- `infra` — NGINX, Docker, implantação

Bugs que atravessam áreas: escolha a área onde está a **causa raiz**, não o
sintoma. Se a causa for genuinamente divisível, reporte o bug na área raiz e
mencione o alcance nas evidências.

### 3. Rascunhar a issue

Monte o draft e **mostre-o ao usuário antes de criar qualquer coisa**. Nada é
publicado sem aprovação explícita.

**Título:** `[BUG] <resumo curto do sintoma em PT-BR>`

**Corpo** (estrutura fixa):

```markdown
## Comportamento esperado

<o que deveria acontecer>

## Comportamento observado

<o que aconteceu, com o erro exato>

## Passos para reproduzir

1. <passo>
2. <passo>
3. <erro acontece>

## Evidências

<stack traces, logs, saídas de testes — trechos reais em blocos de código>

## Arquivos suspeitos

- `<caminho/arquivo.ext>[:linha]` — <por que é suspeito>

## Contexto da sessão

<o que estava sendo feito quando o bug apareceu>

---
> *This was generated by AI during triage.*
```

### 4. Criar a issue

Após aprovação, crie com heredoc:

```bash
gh issue create --title "[BUG] ..." --label "bug,<área>" --body "$(cat <<'EOF'
<corpo do draft>
EOF
)"
```

Se a label de área não existir no repo, crie a issue só com `bug` e avise.

### 5. Adicionar ao Project na coluna "Reports de Bug"

O Project é o de número **2**, dono **CaianFranca**. Resolva os IDs em
runtime — não os hardcode, pois podem mudar:

1. Descubra o ID do project: `gh project view 2 --owner CaianFranca --format json`
2. Descubra o ID do campo **Status** e da opção **Reports de Bug**:
   `gh project field-list 2 --owner CaianFranca --format json`
3. Adicione a issue ao project:
   `gh project item-add 2 --owner CaianFranca --url <url-da-issue>`
4. Defina o Status:
   `gh project item-edit --project-id <id-do-project> --id <id-do-item> --field-id <id-do-campo-status> --single-select-option-id <id-da-opcao-reports-de-bug>`

O passo 3 retorna o ID do item; use-o no passo 4.

### 6. Reportar de volta

Ao final, informe ao usuário:

- Link da issue criada
- Labels aplicadas
- Confirmação de que o item está no Project com Status **Reports de Bug**
